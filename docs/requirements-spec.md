## 3. 프로젝트 결정사항

### 3.1 보드 좌표와 크기

논리적인 플레이 영역은 요구사항에 따라 `20행 × 10열`로 한다.

구현에서는 경계 판정을 단순화하기 위해 다음과 같은 내부 배열을 사용한다.

- 내부 배열: 기본 `22행 × 12열`
- 위쪽 경계: 행 `0`
- 실제 플레이 영역: 행 `1..20`, 열 `1..10`
- 좌우 경계: 열 `0`, `11`
- 아래 경계: 행 `21`
- 행 `0`과 행 `21`은 각각 위쪽·아래쪽 벽으로 사용한다.

현재 블록의 위치는 블록 모양 배열의 왼쪽 위 칸을 기준으로 한다. 새 블록은 기본적으로 `행 1`에서 생성한다. 생성 열은
블록 모양의 너비를 기준으로 플레이 영역 중앙에 오도록 다음과 같이 계산한다.

```text
생성 열 = 1 + floor((플레이 영역 너비 - 블록 모양 너비) / 2)
```

기본 10열 보드에서의 예시는 다음과 같다.

| 블록 모양 너비 | 생성 열 |
|---:|---:|
| 4칸 (`I`) | 4 |
| 3칸 (`J`, `L`, `S`, `T`, `Z`) | 4 |
| 2칸 (`O`) | 5 |

설정에서 보드 크기를 바꾸는 경우 실제 플레이 영역의 행·열이 변경되며, 경계 포함 내부 배열은 항상 각 크기에 맞춰 다시 생성한다.

### 3.2 칸 값

`Board`는 `int[][]`를 사용한다.

| 값 | 의미 |
|---:|---|
| `-1` | 벽 또는 바닥 (`WALL`) |
| `0` | 빈 칸 (`EMPTY`) |
| `1..7` | 7종 블록의 고정 칸. 블록 종류별 고유 값 |

현재 `Board`에 있는 `WIDTH`, `HEIGHT`는 기본값을 의미해야 한다. 설정으로 크기를 변경할 수 있으므로 실제 보드의 크기는 인스턴스 필드로 관리한다.

### 3.3 기본 조작키

설정에서 변경할 수 있는 기본 키는 다음과 같다.

| 기능 | 기본 키 |
|---|---|
| 왼쪽 이동 | Left Arrow |
| 오른쪽 이동 | Right Arrow |
| 한 칸 하강 | Down Arrow |
| 시계방향 회전 | Up Arrow |
| 하드 드롭 | Space |
| 일시정지·재개 | P |
| 현재 게임 종료 | Q |

키가 변경되면 해당 설정을 저장하고 다음 실행에서도 적용한다. 메뉴에서는 방향키 또는 지정된 메뉴 이동키로 항목을 이동하고 Enter로 선택한다.

## 4. 기능 요구사항

### FR-01 시작 메뉴

프로그램 실행 시 시작 메뉴를 표시한다.

메뉴는 최소한 다음 항목을 제공한다.

1. 게임 시작
2. 설정
3. 스코어보드
4. 게임 종료

메뉴 상단에는 게임 이름을 표시한다. 키보드로 메뉴 항목을 이동할 수 있고 Enter 입력으로 선택한다. 메뉴 항목은 이후 추가될 수 있도록 메뉴 목록과 화면 출력 로직을 분리한다.

### FR-02 게임 시작

사용자가 시작 메뉴에서 게임 시작을 선택하면 다음 상태로 초기화하여 게임을 시작한다.

- 보드 초기화
- 현재 블록 생성
- 다음 블록 생성
- 점수 0점
- 게임 상태 `PLAYING`
- 초기 하강 간격 1초

### FR-03 게임 화면

게임 화면은 최소한 다음 정보를 실시간으로 표시한다.

- 블록이 쌓이는 보드
- 다음 블록
- 현재 점수
- 현재 게임 상태 또는 일시정지 안내

보드의 논리 영역은 항상 선택된 크기의 행·열을 정확히 보여야 한다. 벽이나 출력용 여백은 논리 영역과 구분한다.

### FR-04 블록 종류와 생성

다음 7종 블록을 구현한다.

- I
- J
- L
- O
- S
- T
- Z

블록은 생성될 때마다 7종 중 하나를 동일한 확률로 무작위 선택한다. 현재 블록과 다음 블록은 구분하여 관리한다. 각 블록의 고정 칸에는 블록 종류를 식별할 수 있는 값과 출력 표현을 사용한다.

### FR-05 자동 하강과 속도 증가

- 현재 블록은 입력이 없어도 기본 1초에 한 칸씩 아래로 이동한다.
- 일정 수 이상의 블록이 생성되거나 행이 삭제되면 하강 간격을 줄인다.
- 속도는 미리 정한 단계별 값으로 관리한다.
- 일시정지 중에는 하강 타이머와 자동 게임 진행이 멈춘다.
- 재개하면 일시정지 전 게임 상태에서 계속 진행한다.

권장 초기 속도 단계는 다음과 같다.

| 레벨 | 하강 간격 |
|---:|---:|
| 1 | 1000ms |
| 2 | 800ms |
| 3 | 600ms |
| 4 | 400ms |
| 5 이상 | 250ms 이상 |

정확한 단계 상승 조건은 `속도 정책`으로 한 곳에서 관리한다.

### FR-06 블록 이동

현재 블록은 다음 조작을 지원한다.

- 왼쪽으로 한 칸 이동
- 오른쪽으로 한 칸 이동
- 아래로 한 칸 이동
- 시계방향 90도 회전
- 가능한 최저 위치까지 즉시 하강

이동 또는 회전 후 블록의 유효한 칸이 벽, 바닥 또는 고정 블록과 겹치면 해당 입력을 적용하지 않는다. 반복 입력도 누락하지 않고 가능한 한 즉시 처리한다.

### FR-07 충돌과 블록 고정

충돌 판정은 블록의 0이 아닌 칸만 검사한다.

1. 이동 또는 회전 가능 여부를 검사한다.
2. 가능하면 현재 블록 위치를 갱신한다.
3. 아래로 이동할 수 없으면 현재 블록을 보드에 고정한다.
4. 고정 직후 완성 행을 검사한다.
5. 새 현재 블록과 다음 블록을 준비한다.

보드 경계 밖에 있는 유효 블록 칸은 정상적인 이동으로 인정하지 않는다. `CrashDetector`가 이 책임을 담당하더라도 최종적인 보드 변경은 `Board`만 수행한다.

### FR-08 행 삭제

- 보드의 논리 영역 한 행이 모두 블록으로 채워지면 해당 행을 삭제한다.
- 삭제한 행 위의 모든 행을 아래로 이동한다.
- 여러 행이 동시에 완성되면 한 번의 착지 처리에서 모두 삭제한다.
- 삭제 후 새로 생기는 상단 영역은 빈 칸으로 채운다.
- 벽 열과 바닥 행은 행 완성 검사 대상에서 제외한다.

### FR-09 점수

점수는 게임 중 실시간으로 표시한다.

기본 점수 규칙:

- 블록이 한 칸 아래로 이동할 때마다 1점
- 자동 하강과 수동 하강 모두 동일하게 적용
- 하드 드롭도 실제로 이동한 칸 수만큼 점수 적용
- 초기 속도보다 빠른 상태에서 하강한 경우 추가 1점

추가 점수 규칙으로 행 삭제 보너스를 적용한다.

| 삭제 행 수 | 보너스 |
|---:|---:|
| 1 | 100점 |
| 2 | 300점 |
| 3 | 500점 |
| 4 | 800점 |

이는 요구사항에서 직접 제시되지 않은 추가 점수 방식에 해당한다. 점수 계산은 `ScoreCount`에 모으고, 화면·스코어보드가 계산식을 중복 구현하지 않는다.

### FR-10 색맹 모드

설정에서 색맹 모드를 켜고 끌 수 있어야 한다.

- 기본 모드에서는 블록별 색상을 사용한다.
- 색맹 모드에서는 색상만으로 구분하지 않아도 되도록 블록별 문자·패턴·기호를 함께 표시한다.
- 색맹 모드에서도 모양이 유사한 블록을 구분할 수 있어야 한다.
- 색맹 모드 변경은 다음 게임 또는 현재 화면에 즉시 반영한다.

### FR-11 게임 일시정지·재개·재시작·종료

- 게임 중 지정된 키로 일시정지한다.
- 일시정지 중 같은 키를 누르면 재개한다.
- 재시작을 선택하면 현재 게임 보드와 점수를 초기화하고 새 게임을 시작한다.
- 게임 중 지정된 종료키를 누르면 확인 절차 후 메인 메뉴로 이동하거나 게임을 종료한다.
- OS의 Alt-F4만을 유일한 종료 방법으로 사용하지 않는다.

### FR-12 설정

설정 화면은 다음 기능을 제공한다.

- 미리 정의된 보드 크기 최소 3개 중 선택
- 조작키 변경
- 스코어보드 초기화
- 색맹 모드 on/off
- 모든 설정을 기본값으로 복원

권장 보드 크기 프리셋:

| 이름 | 실제 플레이 영역 |
|---|---:|
| Small | 15 × 8 |
| Medium | 20 × 10 |
| Large | 25 × 12 |

설정 변경 후 저장하면 다음 프로그램 실행 시 마지막 설정을 불러온다. 저장 실패 시 기본값으로 계속 실행하고 사용자에게 실패 사실을 알린다.

### FR-13 게임 오버

새 블록을 생성하거나 고정할 위치가 없으면 게임 오버로 전환한다.

- 게임 진행을 중지한다.
- 현재 점수를 확정한다.
- 스코어보드 화면을 표시한다.
- 현재 점수가 순위에 포함되면 이름 입력 화면을 표시한다.
- 이름 입력 후 점수와 이름을 스코어보드에 반영하고 방금 기록을 강조한다.
- 처리 후 메인 메뉴로 돌아가거나 프로그램을 종료한다.

### FR-14 스코어보드

- 이름과 점수를 높은 점수 순으로 정렬한다.
- 최소 상위 10개 기록을 유지하고 표시한다.
- 동일 점수의 정렬 기준은 먼저 기록된 점수를 우선한다.
- 프로그램을 종료해도 기록을 유지한다.
- 설정의 초기화 기능을 사용하기 전까지 기록을 삭제하지 않는다.
- 파일 손상 또는 파일 부재 시 빈 스코어보드로 시작한다.

### FR-15 배포와 실행

- Java 21 이상 환경에서 실행한다.
- Windows 11을 기본 대상 운영체제로 한다.
- 명령 프롬프트에 별도 명령을 입력하지 않고 실행 파일을 더블클릭하여 실행할 수 있어야 한다.
- 실행 파일에 애플리케이션 아이콘을 포함한다.
- Gradle 빌드와 패키징 과정을 문서화한다.

```text
      ├─ DropTest.java
      ├─ TurnTest.java
      ├─ ScoreTest.java
      ├─ SettingTest.java
      ├─ SaveTest.java
      └─ TimerTest.java
```

패키지별 의존 방향은 다음을 따른다.

```text
UI / 입력
    ↓
GameSession
    ↓
feature.move·turn·drop·timer
    ↓
Board ─── CrashDetector
    ↓
Block
```

`feature.move`의 클래스는 이동 명령을 표현하고 `Board`에 이동을 요청한다. 이동 클래스가 보드 배열을 직접 수정하거나 충돌 규칙을 중복 구현하지 않는다. `Board`는 최종 상태 변경을 담당하고 `CrashDetector`는 판정 결과만 제공한다.

### 5.1 진입점과 화면

| 현재 경로 | 책임 |
|---|---|
| `tetris.Main` | 애플리케이션 진입점, 초기 의존성 구성, 메뉴 시작 |
| `tetris.ui.LandingScreen` | 시작 메뉴 화면 |
| `tetris.ui.MenuScreen` | 메뉴 공통 탐색·선택 처리. 필요하면 LandingScreen과 통합 |
| `tetris.ui.BoardScreen` | 보드·다음 블록·점수·게임 상태 출력 |
| `tetris.ui.EndScreen` | 게임 오버 및 종료 후 흐름 |
| `tetris.ui.ScoreBoardScreen` | 스코어보드 출력 |
| `tetris.ui.SettingScreen` | 설정 조회·변경 UI |

현재 화면 클래스가 비어 있으므로, 화면은 게임 로직을 직접 변경하지 않고 공개된 게임 서비스 메서드를 호출하는 방식으로 구현한다.

### 5.2 게임 데이터와 블록

| 현재 경로 | 책임 |
|---|---|
| `tetris.feature.data.Board` | 보드 배열 소유, 초기화, 이동 가능 여부, 블록 배치, 줄 삭제, 게임 오버 검사 |
| `tetris.component.block.Block` | 블록 모양, 위치, 회전 공통 기능 |
| `IBlock` 등 7개 클래스 | 각 테트로미노의 초기 모양과 블록 식별값 |
| `tetris.feature.timer.RandomSelect` | 7종 블록의 동일 확률 선택 |

`Board`가 보드 관련 변경을 모두 수행한다. 외부 클래스가 내부 배열을 직접 수정하지 않도록 하고, 필요하면 읽기 전용 조회 또는 복사본을 제공한다.

현재 `Board`의 `createDefaultBoard()`는 생성자에서 반환값으로 사용되고 있으나 메서드가 `void`로 선언되어 있어 수정이 필요하다. 또한 설정 크기를 지원하려면 `WIDTH`, `HEIGHT`는 기본값이고 실제 크기는 인스턴스 값이어야 한다.

### 5.3 이동·충돌·회전·드롭

| 현재 경로 | 책임 |
|---|---|
| `tetris.feature.crash.CrashDetector` | 순수 충돌 판정 보조 로직. 보드 변경은 수행하지 않음 |
| `tetris.feature.move.MoveBlockLeft/Right/Down` | 이동 요청을 게임 또는 Board에 전달 |
| `tetris.feature.turn.BlockTurnRight` | 시계방향 90도 회전 요청 처리 |
| `tetris.feature.drop.BlockDrop` | 하드 드롭 처리 및 이동 칸 수 계산 |
| `tetris.feature.drop.ShiftRowDown` | 줄 삭제 후 행 이동 |
| `tetris.feature.clear.LineClear` | 완성 행 하나의 삭제 판정·처리 |
| `tetris.feature.clear.MultiLineClear` | 한 번에 여러 행 삭제 처리 |

이동·회전·드롭 클래스가 각각 보드를 직접 조작하면 상태 불일치가 발생하므로, 최종 상태 변경은 `Board`의 메서드로 통일한다.

### 5.4 게임 진행과 상태

`tetris.feature.game` 패키지는 게임 한 판의 진행과 상태를 담당한다.

| 현재 경로 | 책임 |
|---|---|
| `tetris.feature.game.GameSession` | 현재 블록·다음 블록·Board를 연결하고 게임 흐름을 조정 |
| `tetris.feature.game.GameState` | 게임 진행 상태를 표현하는 값 |

`GameState`에는 게임 진행 상태만 둔다.

- `LOADING`: 게임 시작 전 초기화 및 블록 생성 준비
- `PLAYING`: 게임 진행 중
- `PAUSED`: 일시정지
- `GAME_OVER`: 더 이상 블록을 배치할 수 없는 상태
- `ENDED`: 현재 게임 종료

`MENU`, `SETTINGS`, `SCOREBOARD`는 게임 상태가 아니라 애플리케이션 화면 흐름에서 관리한다.

`GameSession`은 다음을 담당한다.

- 현재 `GameState` 관리
- 현재 블록과 다음 블록 연결
- 입력 이벤트를 이동·회전·드롭으로 변환
- 타이머 이벤트 처리
- 블록 고정 후 행 삭제·점수·새 블록 생성 순서 조정
- 게임 오버 후 화면 전환

`Board`는 보드 상태와 보드 규칙을 담당하고, `GameSession`은 게임의 시간적 흐름을 담당한다.

`GameState`의 기본 전이는 다음과 같다.

```text
LOADING -> PLAYING
PLAYING -> PAUSED -> PLAYING
PLAYING -> GAME_OVER -> ENDED
PLAYING -> ENDED
```

### 5.5 점수·설정·저장

| 현재 경로 | 책임 |
|---|---|
| `tetris.feature.score.ScoreCount` | 하강·속도·행 삭제 점수 계산 |
| `ScoreReset` | 점수 또는 스코어보드 초기화 정책 |
| `ScoreBoardSort` | 점수 내림차순 정렬 및 상위 기록 제한 |
| `tetris.feature.setting.BoardSizeChange` | 보드 크기 프리셋 선택 |
| `ColorChange` | 색맹 모드 및 출력 표현 선택 |
| `ControlKeySet/Change` | 키 기본값·변경·유효성 검사 |
| `tetris.feature.save.SettingSave` | 설정 영속화 |
| `ScoreSave` | 현재 점수 저장 보조 |
| `ScoreBoardSave` | 스코어보드 저장·불러오기 |
| `ControlKeySave` | 조작키 저장·불러오기 |
| `BlockSave` | 필요할 경우 게임 재개용 블록 상태 저장 |

간단한 1차 구현에서는 텍스트 기반 파일 저장을 사용한다. 저장 위치는 패키지 내부가 아니라 사용자 쓰기 권한이 있는 애플리케이션 데이터 디렉터리로 정한다. 파일 포맷과 위치는 README에 명시한다.

### 5.6 기존 버튼 클래스

`tetris.component.button`의 버튼 클래스는 각 화면에서 발생하는 사용자 명령을 의미한다. 버튼 클래스가 보드 배열이나 파일을 직접 변경하지 않고, 해당 기능 서비스 또는 `GameSession`을 호출하도록 한다.

## 6. 핵심 상태 흐름

```text
START
  -> MENU
  -> PLAYING
      -> PAUSED -> PLAYING
      -> GAME_OVER
          -> NAME_INPUT (신기록인 경우)
          -> SCOREBOARD
          -> MENU 또는 EXIT
  -> SETTINGS -> MENU
  -> SCOREBOARD -> MENU
  -> EXIT
```

게임 진행 중의 한 사이클은 다음 순서를 따른다.

```text

  -> 완성 행 삭제
  -> 점수 및 속도 갱신
  -> 다음 블록을 현재 블록으로 교체
  -> 화면 갱신
```

## 11. 현재 구현과의 차이

현재 저장소는 패키지와 클래스 골격이 먼저 생성된 상태이며, 실제 동작 구현은 일부 블록 모델과 `CrashDetector`에 한정되어 있다.

우선 해결해야 하는 항목은 다음과 같다.

1. `Board.createDefaultBoard()`의 반환 타입과 생성자 사용을 일치시킨다.
2. 내부 보드 인덱스 정책을 확정하고 왼쪽 벽을 빈 칸으로 덮어쓰지 않도록 한다.
3. `Board`가 내부 배열을 소유하고 보드 변경을 단일 책임으로 수행하게 한다.
4. `BoardCondition`과 `BlockCondition`의 필요성을 재검토하고, 사용하지 않으면 제거한다.
5. 설정 가능한 크기를 위해 `WIDTH`, `HEIGHT`를 단순한 고정 실제 크기로 사용하지 않는다.
6. `GameSession`과 `GameState`의 실제 게임 흐름을 구현한다.
7. 현재 빈 테스트 클래스에 단위 테스트를 작성한다.
8. `Main`에서 실행 가능한 메뉴 흐름을 연결한다.
