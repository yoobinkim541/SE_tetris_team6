## 팀원 리뷰 후속 수정

팀원의 #138 권고를 코드와 대조하고 다음을 회귀 테스트로 재현했다.

- Q 확인창은 P1 기권 / P2 기권 / 취소를 제공한다. 취소가 기본 선택이고 각 기권은 상대 승리를 표시한다. 기존 boolean 확인 콜백은 P1 기권 호환 경로로 유지한다.
- 자동 Pause 중 경기가 FINISHED로 바뀌면 확인창을 열지 않는다. 모달 창 중 이미 결과가 확정돼도 추가 기권을 보내지 않는다.
- 공격은 같은 Spawn 경계에서 두 번 삽입할 수 없다. 상단 초과 GAME_OVER는 Spawn 대기를 정리한다.
- 컨트롤러 구독/초기 스냅샷 처리 실패는 입력 바인딩·클라이언트·타이머를 정리한다.
- 실제 클라이언트 이동 테스트는 중력으로 통과할 수 없도록 가로 이동을 확인하고 구독 해제 후 후속 콜백이 없는지 검증한다. 재시작은 입력 래치와 시퀀스 초기화를 검증한다.
- 상단 초과 종료의 revision은 한 번만 증가한다.
- 기본 GUI 검증은 KeyEvent를 사용하고, Robot OS 키 주입은 명시적인 `-PnativeInput=true`에서만 실행한다. 물리 키보드 검증으로 이름을 바꿔 기록하지 않는다.

## 물리 키보드 인수표

실행 파일: `build/jpackage/image-v2/SE Tetris/SE Tetris.exe` 또는 Java 21에서 `java -jar build/libs/SE-Tetris.jar`.

1. 메인 메뉴 → 대전 → 로컬 일반 대전을 연다.
2. P1 ←와 P2 D를 함께 눌러 두 보드가 각자 움직이는지 확인한다. P1 ↓와 P2 S, P1 ↑와 P2 W, Space와 F 조합도 확인한다.
3. 이동키를 누른 채 P로 멈추고 키를 뗀 뒤 P로 재개한다. 이전 이동이 저절로 이어지지 않아야 한다.
4. 다른 창으로 전환한 뒤 돌아온다. 양쪽이 Pause되고 눌림이 남지 않아야 한다.
5. Q → 취소로 복귀하고, 다시 Q → P2 기권을 선택한다. P1 승리·기권이 표시되고 Enter로 모드 선택에 돌아와야 한다.

- 확인 장비/키보드: 미입력
- 확인자/결과: 사용자 직접 미확인. 이후 자동 검증 대체 예외 승인.
- 상태: 물리 확인 자체는 미완료이며, 기능 인수는 사용자 승인에 따라 자동 검증으로 대체한다. 실제 장비 결과를 만들어 기록하지 않는다.

## 패키지 복구와 최종 회귀

main의 별도 Package 작업은 테스트 전 Gradle 9.7.1 ZIP 다운로드 timeout/HTTP 504로 세 번 실패했다. #141에서 이미 성공한 CI와 동일한 setup-gradle v4 / Gradle 8.10.2 설치 방식을 적용했다. 테스트·GUI·JAR·ZIP·EXE smoke·태그 Release 조건은 유지한다. 실제 Package 실행 42471970523은 빌드·EXE smoke·ZIP/JAR 업로드까지 통과했다.

최종 main PR의 Linux 실행에서 기존 dispatcher 스레드 테스트 경합도 확인했다. 이미 완료된 future의 늦은 thenRun 등록이나 get의 완료 처리가 테스트 스레드에서 콜백을 관측하게 할 수 있었다. 두 dispatcher를 잠시 대기시켜 콜백을 먼저 등록하고, 콜백을 받은 뒤 future를 조회하도록 테스트 순서를 고정했다. 원래 스레드 동일성 단언과 실제 소켓 검증은 유지하며 테스트를 생략하지 않는다.
