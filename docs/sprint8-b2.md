# Sprint 8 B2: 대전 표시와 결과 화면

## 제공 API

- `BattleKeyMap.guide()`는 현재 키 설정에서 P1/P2의 다섯 동작과 공통 Pause/Quit 안내를 만든다. 키 변경 후 새 안내 문자열로 화면을 생성한다.
- `BattlePanel(boolean colorBlind, String guide)`는 전달된 안내를 표시하며 접근성 설명에도 제공한다. 기존 `BattlePanel(boolean)`은 기본 키 설정 안내를 사용한다.
- `BattleResultPanel(Runnable onModes, Runnable onMain)`은 `setSnapshot(MatchSnapshot)`으로 FINISHED 스냅샷만 받는다. 결과는 로컬 시점과 무관하게 P1/P2 또는 무승부, 종료 사유, 두 점수를 표시한다. `getSummaryText()`와 `getScoresText()`로 표시 문구를 읽을 수 있다.
- 결과의 `모드 선택` 버튼/Enter와 `메인 메뉴` 버튼/Escape는 전달된 콜백만 호출한다. 키 바인딩은 결과 패널의 `WHEN_IN_FOCUSED_WINDOW`에만 설치한다. 컨트롤러는 결과 화면을 보이기 전에 게임 입력 라우터를 닫는다.

## 표시 경계

공격 값 9는 `BlockType` 인덱싱 전에 별도로 처리한다. 공격칸 X와 회색 W는 색맹·작은 셀에서도 무늬로 구분한다. 두 보드의 대기열은 공통 스냅샷의 행과 구멍을 위에서 아래 순서 그대로 표시한다. 비어 있는 슬롯은 빈칸으로 그린다.

결과 패널은 엔진이나 저장소를 소유하지 않는다. 싱글 GameOver/점수 저장 경로를 호출하지 않는다. 모드 선택·메인 메뉴 연결은 컨트롤러의 책임이다.

## 검증

테스트를 먼저 추가하고 누락된 `guide()`, 생성자, 결과 패널로 인한 컴파일 RED를 확인했다. 첫 기본 메모리 실행은 테스트 실행 전 JVM 메모리 확보 실패로 중단됐으며, RED와 구분한다.

추가 테스트는 결과 승자/무승부·세 종료 사유·양쪽 점수·잘못된 단계 거절, 버튼/키 콜백, 변경된 키 안내, 양쪽 플레이어의 대기열 0~10줄 전체 구멍/행 순서, 두 팔레트의 7/14/27픽셀 W/X 무늬를 확인한다.

읽기 전용 AI 리뷰에서 남은 수정 지적은 없었다. 이 리뷰는 팀원 리뷰를 대신하지 않는다. 키 테스트는 Swing 액션 호출이며 물리 키보드 동시 입력/롤오버 검증이 아니다. 픽셀 검증은 결과 화면이나 안내 문구의 실기 가독성 인증이 아니다.
