# 3차 요구사항 결정 기록 (S7-A1)

원문에서 정해진 것, 팀이 정한 것, 교수님 확인이 필요한 것을 나눈다. 원문이 모호한 부분은 e-class 문의 대상이다 (Req3 p14).

## A. 원문 필수 (바꿀 수 없음)

| ID | 내용 | 근거 |
|---|---|---|
| F-01 | 2줄 이상 삭제해야 공격 | p4 |
| F-02 | 넘어가는 줄은 마지막 블록 칸을 제외한 모양 그대로 | p4–5 |
| F-03 | 공격 줄은 현재 블록 처리 뒤, 다음 Spawn 전에 보드 아래에 추가 | p4 |
| F-04 | 대기열 최대 10줄. 가득 차 있으면 무시, 넘치면 가장 아래쪽을 잘라 냄 | p6 |
| F-05 | 대전 결과는 스코어보드에 기록하지 않음 | p5 |
| F-06 | P2P 모드는 호스트만 고름. 둘 다 '게임 시작'을 눌러야 시작 | p8 |
| F-07 | P2P 경기 후 연결 직후 대기 상태로 복귀 | p9 |

## B. 팀 결정 (계약 v1에 반영됨, 리뷰로 바꿀 수 있음)

| ID | 결정 | 이유 |
|---|---|---|
| D-01 | 대전 모드는 별도 enum `VersusMode`(NORMAL/ITEM/TIME_LIMIT)로 두고, 싱글 `GameMode`(CLASSIC/ITEM)는 그대로 둔다 | 싱글 스코어보드·저장 형식을 건드리지 않기 위해 |
| D-02 | **동시 패배**: 로컬은 EDT 한 스레드가 순서대로 처리하므로 먼저 Spawn에 실패한 쪽이 진다. P2P는 호스트가 판정한다(호스트 권위) | 같은 프레임 안 처리 순서가 결정적이라 무승부가 생기지 않음 |
| D-03 | **Pause**: 로컬 대전은 한쪽이 눌러도 두 보드가 함께 멈춘다. PAUSE·QUIT은 PlayerId와 무관하게 한 번만 보낸다(B의 키 라우터와 같음). P2P는 Pause 없음 — 누르면 무시한다 | 상대 동의 없이 상대 게임을 멈추면 악용 가능 |
| D-04 | 공격 칸 값은 9(`VersusRules.ATTACK_CELL`), 회색으로 그린다 | B의 임시 DTO와 같은 값. 블록 색 1–8과 겹치지 않음 |
| D-05 | TIME_LIMIT 기본 2분(120,000 ms). 난이도는 NORMAL 기본, 양쪽 같은 난이도 | 시연 시간 고려 |
| D-06 | **시간 종료 동점**은 무승부(`MatchResult.timeUpDraw()`) | 원문은 "점수가 더 높은 사람" 만 언급 |
| D-07 | 남은 시간은 낙하 타이머(`GameClock`)가 아니라 별도 `MatchClock`의 마감 시각으로 판정한다. Pause 동안은 마감 시각을 뒤로 민다 | GameClock은 매 Spawn·Pause마다 재시작되어 경기 전체 시간을 셀 수 없음 |
| D-08 | 공격 줄 삽입은 `PreSpawnHook`에서 한다. 싱글은 `PreSpawnHook.NONE`이라 동작이 그대로다 | F-03의 "다음 Spawn 전" 경계를 한 곳으로 고정 |
| D-09 | 아이템 모드 대전에서 L 아이템 등으로 지운 줄도 공격 줄 수에 포함하고, 줄 번호는 중복을 뺀 합집합. 칸 단위로 지우는 아이템은 줄 수에 넣지 않는다 | S7-A2 수용 기준 |

## C. 교수님 확인 필요 (e-class 문의)

| ID | 질문 | 임시 처리 |
|---|---|---|
| Q-01 | 시간제한 모드 동점은 무승부로 처리해도 되는가 | D-06 |
| Q-02 | P2P 대전에서 Pause를 제공하지 않아도 되는가 | D-03 |
| Q-03 | 대전 모드에서도 난이도 설정(easy/hard 확률·속도)을 적용해야 하는가 | 설정에 포함, 기본 NORMAL |
| Q-04 | 무게추 등 '줄을 지우지 않고 칸을 지우는' 아이템은 공격을 만들지 않아도 되는가 | D-09 |
