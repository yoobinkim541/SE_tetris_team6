# S10 C 트랙: heartbeat·지연·끊김(S10-C1)과 재대전·최근 IP(S10-C2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** P2P 연결의 지연·끊김을 합의된 기준으로 판정해 알리고, 정상 경기 뒤 같은 연결로 재대전하며, 접속에 성공한 주소 5개를 저장한다.

**Architecture:** 판정은 시계를 주입받는 순수 상태 기계 `ConnectionHealth`가 하고, `SocketLobbyClient`가 연결마다 heartbeat `MatchPulse`로 PING을 보내며 받은 프레임·PONG을 넘긴다. 상태 변화는 새 `LinkHealth` 구독으로 알린다. 최근 주소는 기존 저장소 패턴(`SettingsRepository`/`JsonSettingsRepository`)을 따라 `RecentPeers`/`JsonRecentPeerRepository`로 만들고, 디스크 쓰기는 EDT 밖 실행기에서 한다.

**Tech Stack:** Java 21, Swing EDT dispatcher, JUnit 5, Jackson(`feature.save.JsonFile`), Gradle Wrapper.

**Spec:**

## Review Focus

1. heartbeat 타이머가 연결 종료·`leave()`·`close()`·재접속 뒤에도 남아 이전 연결 기준으로 LOST를 발행하는 경우 → 이전 연결의 타이머는 아무것도 하지 않음.
2. 상대 PONG이 아니라 위조·지난 nonce의 PONG이 오는 경우 → RTT 계산에 쓰지 않음(프레임 수신으로만 침).
3. 끊김(LOST)과 상대의 정상 나가기(LEAVE)가 같은 INITIAL로 보이는 경우 → `LinkHealth`가 서로 다른 상태를 한 번씩 알림.
4. `recent-peers.json`이 손상·쓰기 불가·폴더 없음인 경우 → 접속은 계속되고 예외가 EDT로 새지 않음.
5. 재대전 직후 이전 판의 STATE/INPUT/RESULT가 늦게 도착하는 경우 → 새 판 상태가 바뀌지 않음.

### Task 1: 연결 상태 판정기

**Files:** Create `HeartbeatPolicy.java`, `ConnectionHealth.java`; Test `ConnectionHealthTest.java`

**Interfaces — Produces:**
- `public record HeartbeatPolicy(long intervalMillis, long lagRttMillis, int lagRttCount, long lagSilenceMillis, long lostSilenceMillis, long recoverRttMillis, int recoverRttCount) { public static final HeartbeatPolicy DEFAULT = new HeartbeatPolicy(500, 200, 3, 1_500, 5_000, 150, 3); }` (모든 값 > 0, `recoverRttMillis < lagRttMillis`, `lagSilenceMillis < lostSilenceMillis` 검사)
- `public final class ConnectionHealth { public enum Status { NORMAL, LAGGING, LOST } public ConnectionHealth(HeartbeatPolicy p, long nowMillis); public void onFrame(long nowMillis); public void onRtt(long rttMillis, long nowMillis); public Status evaluate(long nowMillis); public Status status(); public long lastRttMillis(); /* 없으면 -1 */ }`

**판정 규칙:**
- `silence = now - 마지막 onFrame/onRtt 시각`(생성 시각으로 시작). `silence >= lostSilenceMillis` → LOST(되돌릴 수 없음, 이후 모든 호출 무시).
- `onRtt`: `rtt > lagRttMillis`면 high++·low=0, `rtt <= recoverRttMillis`면 low++·high=0, 그 사이면 둘 다 0. `onRtt`는 프레임 수신으로도 친다.
- NORMAL → LAGGING: `high >= lagRttCount` 또는 `silence >= lagSilenceMillis`.
- LAGGING → NORMAL: `low >= recoverRttCount` 그리고 `silence < lagSilenceMillis`. 전환 시 high/low 0.

  - `처음에는_NORMAL이다`
  - `RTT_201ms_3회면_LAGGING이고_2회면_NORMAL`
  - `정확히_200ms는_지연이_아니다` (경계)
  - `무수신_1499ms는_NORMAL_1500ms는_LAGGING`
  - `무수신_4999ms는_LOST가_아니고_5000ms는_LOST`
  - `프레임을_받으면_무수신_시간이_다시_시작된다`
