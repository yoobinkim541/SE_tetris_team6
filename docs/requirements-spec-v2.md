## 2. 난이도

- **DIF-1** 난이도는 `EASY`, `NORMAL`, `HARD` 세 가지다. 설정 화면에서 고르고(§11), 기본값은 `NORMAL`이다. **[확정]**
- **DIF-2** 난이도는 **일반 모드에만** 적용한다. 아이템 모드는 항상 `NORMAL` 규칙으로 진행한다. **[제안]** **[확인]**
  - 이유: 요구사항 p.3은 "기존의 일반 게임 모드에 난이도 설정을 추가"라고 적었다. 아이템 모드에도 적용하려면 스코어보드 분류가 4개에서 6개로 늘어난다.
- **DIF-3** 난이도별 값 **[확정]**

| 난이도 | I블록 가중치 (나머지 6종 = 10) | 레벨당 낙하 간격 감소폭 `step` | 추가 점수 규칙 |
|---|--:|--:|---|
| EASY | 12 (+20%) | 160 ms (−20%) | 없음 |
| NORMAL | 10 | 200 ms | 없음 |
| HARD | 8 (−20%) | 240 ms (+20%) | 없음 |

- **DIF-4** (v1.2 LVL-2 변경) 낙하 간격 `interval(level) = max(250, 1000 − step × (level − 1))` ms. **[제안]**
  - Level 1은 모든 난이도에서 1000 ms다(1차 요구사항 "1초 낙하"). Level이 오를 때 빨라지는 폭만 달라진다.
  - NORMAL은 v1.2 식 `max(250, 1200 − 200 × level)`과 모든 Level에서 같은 값이다.
  - Level 상승 조건(블록 10개, 줄 5개, v1.2 LVL-3)은 바꾸지 않는다. 요구사항은 "줄 삭제에 따라 증가하는 속도"라고 썼지만, 블록 수에 따른 상승에도 같은 `step`을 쓴다. 두 상승을 따로 계산하면 같은 Level인데 속도가 달라져 Level 표시가 의미를 잃기 때문이다. **[제안]**

| Level | 1 | 2 | 3 | 4 | 5 | 6 이상 |
|---|--:|--:|--:|--:|--:|--:|
| EASY | 1000 | 840 | 680 | 520 | 360 | 250 |
| NORMAL | 1000 | 800 | 600 | 400 | 250 | 250 |
| HARD | 1000 | 760 | 520 | 280 | 250 | 250 |

- **DIF-5** 난이도는 게임 시작 시점의 설정값으로 정하고, 그 판이 끝날 때까지 바뀌지 않는다. Restart는 같은 난이도로 새 판을 시작한다. 설정 화면은 Main Menu에서만 들어갈 수 있으므로(v1.2 §9) 게임 중 변경은 없다. **[확정]**
- **DIF-6** 게임 화면 정보 패널에 `MODE`와 `DIFFICULTY`를 표시한다. 게임 용어이므로 영문으로 표시한다(v1.2 §9.2). **[제안]**
- **DIF-7** 난이도 값 계산은 `Difficulty` enum 한 곳에 둔다(`iWeight()`, `levelStepMillis()`). `LevelPolicy`는 생성자에서 `Difficulty`를 받는다. **[제안]**

## 3. 가중치 블록 생성 (Roulette Wheel Selection)

- **GEN-1** (v1.2 BLK-2 변경) 다음 블록은 가중치에 비례하는 확률로 **독립적으로** 고른다. 블록 `k`의 확률은 `w_k / Σw`다. 7-bag은 쓰지 않는다. **[확정]**

| 난이도 | Σw | I 확률 | 나머지 6종 각각 |
|---|--:|--:|--:|
| EASY | 72 | 16.67% | 13.89% |
| NORMAL | 70 | 14.29% | 14.29% |
| HARD | 68 | 11.76% | 14.71% |

- **GEN-2** 구현: 블록 종류와 무관한 범용 클래스 `WeightedRandom<T>`가 누적 가중치 배열과 이분 탐색(`Random.nextInt(Σw)` 한 번)으로 고른다. `WeightedBlockGenerator`는 `WeightedRandom<BlockType>`을 감싸 `BlockGenerator`를 구현한다. **[제안]**
  - stochastic acceptance(Lipowski 2012)는 기대 시도 횟수가 `max(w) / 평균(w)`(이 문서의 값으로 약 1.03~1.17)라 역시 충분히 빠르다. 하지만 정수 가중치 7개에서는 누적합 방식이 더 단순하고 결정적이다.
  - 가중치는 0 이상 정수이고 합은 1 이상이어야 한다. 위반하면 생성자가 `IllegalArgumentException`을 던진다.
- **GEN-3** `RandomBlockGenerator`(균등)는 삭제한다. 균등 선택은 가중치가 모두 같은 `WeightedBlockGenerator`로 대신한다. **[제안]**
- **GEN-4** **실제 게임이 쓰는 생성기와 테스트가 검증하는 생성기는 같은 클래스**다. `MainFrame`은 `new WeightedBlockGenerator(difficulty.weights(), random)`으로 게임을 만들고, 테스트는 같은 생성자에 시드를 고정한 `Random`을 넣는다. **[확정]**
- **GEN-5** 분포 단위 테스트 **[확정]**
  - 반복 횟수 **10,000회**(요구사항 최소 1,000회). 시드를 고정해 결과가 매번 같다.
  - 판정: 블록마다 `|관측 비율 − 기대 비율| ≤ 0.05`. 요구사항의 "오차범위 ±5%"는 **비율의 절댓값 5%p**로 해석한다(예: 기대 40% → 35%~45%). **[확인]**
  - 대상: ① EASY·NORMAL·HARD 가중치 각각 ② 요구사항 예시인 4종 중 B만 2배(`{A:1, B:2, C:1, D:1}` → 40/20/20/20). ②는 `WeightedRandom<T>`로 검증한다.
  - 참고: 10,000회에서 비율의 표준편차는 최대 약 0.5%p라, 코드에 문제가 없으면 5%p를 넘을 일이 사실상 없다.

## 4. 줄 삭제 애니메이션

- **ANI-1** 지워질 줄(과 아이템이 지울 칸)을 **흰색으로 150 ms 동안 한 번** 표시한 뒤 지운다. **[제안]**
- **ANI-2** 애니메이션 동안의 상태는 `GameState.CLEARING`이다. **[제안]**
  - 이동·회전·Soft/Hard Drop 입력과 자동 낙하는 무시한다.
  - Pause 키, Quit 키, 창 포커스 이탈은 동작한다. CLEARING에서 Pause하면 Resume 때 150 ms를 처음부터 다시 센다(v1.2 TMR-3과 같은 원칙).
- **ANI-3** 타이밍은 기존 `GameClock`을 그대로 쓴다. Lock 후 지울 대상이 있으면 `clock.start(150)`을 걸고, CLEARING 상태에서 `tick()`이 오면 삭제·점수·Spawn을 마저 수행한다(§5 L4~). 테스트는 가짜 시계로 `tick()`을 직접 호출해 검증한다(v1.2 TMR-2). **[제안]**
- **ANI-4** 지울 대상이 없으면 CLEARING을 거치지 않고 바로 Spawn한다. 줄 삭제가 없는 블록의 체감 속도는 1차와 같다. **[제안]**
- **ANI-5** `GameSnapshot`에 `clearingCells`(흰색으로 그릴 칸 목록, CLEARING이 아니면 빈 목록)를 추가한다. UI는 이 칸을 흰색으로 그리고 글자는 그리지 않는다. **[제안]**
- **ANI-6** 무게추가 내려가며 지우는 칸(§8.2)에는 애니메이션을 넣지 않는다. 한 칸 내려갈 때마다 깜빡이면 무게추가 지나치게 느려진다. **[제안]**

### 4.1 GameState 전이 추가 (v1.2 §8.2에 더함)

| From | To | 트리거 |
|---|---|---|
| PLAYING | CLEARING | Lock 후 지울 대상 R ∪ C가 비어 있지 않음 |
| CLEARING | PLAYING | 150 ms 경과 → 삭제·점수·Spawn 성공 |
| CLEARING | GAME_OVER | 150 ms 경과 → 삭제·점수 후 Spawn 충돌 |
| CLEARING | PAUSED | Pause 키, 창 포커스 이탈, Quit 확인창 표시 |
| PAUSED | CLEARING | CLEARING에서 Pause했던 판을 Resume (150 ms 다시 시작) |

## 5. 블록 사이클 파이프라인 (v1.2 §4 대체)

```text
[하강 시도]  성공 → score += Level      실패 → (무게추면 §8.2 분쇄 하강) / 아니면 LOCK
[Hard Drop]  d칸 이동 → score += d × Level → LOCK        (무게추는 §8.2)

LOCK
  L1  현재 블록 칸을 보드에 기록 (값 1..7, 무게추는 8)
  L2  지울 대상 수집 (보드는 아직 바꾸지 않는다)
        R = 완성 행 ∪ (L 아이템 칸이 있는 행)
        C = (B·V 아이템이 지울 칸) − (R에 속한 칸)
        지속 아이템(D, S)이면 효과 등록                         // §8.4, §8.5
  L3  R ∪ C 가 비어 있지 않으면 → CLEARING, clock.start(150), 여기서 대기
                                  (150 ms 뒤 tick()에서 L4부터 이어서 수행)
  L4  C 의 칸을 비움 (위 칸은 내려오지 않음) → R 의 행 삭제·압축 (CLR-2)
  L5  score += bonus(|R|) × 점수배율(D) + |C| × 10           // §8.6
  L6  lines += |R|;  LevelPolicy.onLinesCleared(|R|)          // v1.2 L5와 같음
  L7  (아이템 모드) 누적 줄이 10의 배수를 넘었으면 itemPending = true   // §7
  L8  이번 Lock 전부터 D 효과가 있었으면 남은 블록 수 −1 (이번 Lock에서 새로 얻은 D는 세지 않음)
  → SPAWN

SPAWN
  S1  current = queue.pop();
      queue.append( itemPending ? 아이템 블록 생성 : 일반 블록 생성 );  itemPending = false
  S2  Spawn 충돌? YES → GAME_OVER
  S3  blockCounter += 1 … (v1.2와 같음)
      S 남은 블록 수 > 0 이면 → 이 블록은 슬로우 대상, 남은 블록 수 −1
  S4  이 블록의 낙하 간격 = interval(Level) × (슬로우 대상이면 1.5) 로 타이머 재시작
```

- 이 블록의 낙하 간격은 블록이 Lock될 때까지 유지한다. Resume·확인창 취소 때 타이머를 다시 시작할 때도(v1.2 TMR-3) `LevelPolicy`가 아니라 **현재 블록의 낙하 간격**을 쓴다. **[제안]**

- **PIPE-5** `|R| ≤ 4`가 항상 성립한다. 완성 행과 L 행은 모두 방금 Lock한 블록이 걸친 행이고, 블록 행렬은 최대 4행이기 때문이다. 따라서 v1.2 CLR-3과 `bonus(n)`의 정의역(0..4)을 그대로 쓴다. **[제안]**
- **PIPE-6** 아이템 칸은 Lock되면 **일반 블록 칸**(그 블록 종류 값 1..7)으로 기록된다. 보드에는 아이템 정보가 남지 않는다. 아이템 효과는 L2에서 한 번만 계산한다. **[제안]**
- **PIPE-7** v1.2 PIPE-1~4는 그대로 유지한다. Level은 L6과 S3에서만 바뀐다. **[확정]**

### 5.1 검증용 시나리오

| 상황 | 결과 |
|---|---|
| NORMAL, Level 1, 바닥 행에 9칸이 찬 상태에서 I를 세로로 넣어 1줄 완성 | CLEARING 1회(150 ms) → 1줄 삭제, +100, 새 블록 Spawn |
| 아이템 모드, 꽉 차지 않은 행에 `L` 칸을 두고 Lock, 같은 Lock으로 다른 1줄이 완성됨 | `|R| = 2` → +300, lines += 2 |
| 누적 9줄에서 2줄 삭제 | L7에서 itemPending → S1에서 큐 뒤에 아이템 블록이 들어가 Next에 보인다 |
| CLEARING 중 Pause → Resume | 150 ms를 처음부터 다시 센 뒤 삭제 |
| CLEARING 중 Hard Drop 키 | 무시 (상태 불변) |

## 7. 아이템 등장 규칙

- **ITM-1** 아이템 모드에서는 **누적 삭제 줄이 10, 20, 30… 을 넘을 때마다** 다음 Spawn의 S1 단계에서 큐 뒤에 새로 들어가는 블록을 아이템 블록으로 만든다. 그 블록이 Next 영역에 새로 나타나는 블록이다(p.7). **[확정]**
  - 판정: `floor(이전 누적 줄 / 10) < floor(새 누적 줄 / 10)`.
  - 한 번의 Lock은 최대 4줄이므로 한 번에 10의 배수 두 개를 넘는 경우는 없다.
  - 아이템으로 지운 줄(`L`)도 누적 줄에 포함한다. `B`·무게추가 지운 칸은 줄이 아니므로 포함하지 않는다.
- **ITM-2** 아이템 종류는 `L`, `W`(무게추), `B`, `D`, `S` 5종 중 **균등 확률(각 20%)**로 고른다. **[제안]**
- **ITM-3** `W`면 블록 자체가 무게추다(§8.2). 나머지면 가중치 생성기(GEN-1, NORMAL 가중치)로 일반 블록을 하나 만들고, 그 블록의 **값 있는 칸 4개 중 하나를 균등 확률로** 아이템 칸으로 정한다(p.8: "붙는 위치는 무작위"). **[확정]**
- **ITM-4** 아이템 칸은 블록과 함께 회전한다. 구현은 `Block`에 `shape`와 같은 크기의 아이템 표시를 두고 `rotateClockwise`·`copy`에서 같이 돌리고 복사한다. **[제안]**
- **ITM-5** 일반 모드에서는 아이템이 나오지 않는다. **[확정]**
- **ITM-6** 아이템 블록 생성은 `ItemBlockGenerator`가 맡는다. `ItemBlockGenerator`는 `BlockGenerator`를 감싸는 데코레이터로, `requestItem()`이 불린 뒤 첫 `next()` 한 번만 아이템 블록을 돌려준다. 아이템 종류 선택은 `WeightedRandom<ItemType>`(가중치 모두 1)을 쓴다. **[제안]**

## 8. 아이템 상세 (평가 팀 확인용)

공통 표시 규칙(§12): 아이템 칸은 **흰 배경 + 검은 굵은 글자**로, 블록 색·색맹 모드와 무관하게 같다. 기본 블록 칸은 모두 `O`로 그린다.

### 8.0 한눈에 보기

| 문자 | 이름 | 출처 | 형태 | 발동 시점 | 효과 | 점수 |
|---|---|---|---|---|---|---|
| `L` | 줄 삭제 | 요구사항 | 일반 블록의 1칸 | Lock | 그 칸의 행을 꽉 차지 않아도 삭제 | 줄 삭제 점수 (기존 방식) |
| `W` | 무게추 | 요구사항 | 블록 전체 (너비 4) | 첫 착지 | 아래 칸을 지우며 바닥까지 하강 | 없음 |
| `B` | 폭탄 | 팀 | 일반 블록의 1칸 | Lock | 아이템 칸 중심 3×3 칸 삭제 | 지운 칸당 10점 |
| `D` | 점수 2배 | 팀 | 일반 블록의 1칸 | Lock | 그 블록과 다음 블록 10개의 줄 삭제 점수 2배 | 효과 자체 |
| `S` | 슬로우 | 팀 | 일반 블록의 1칸 | Lock | 다음 블록 10개의 낙하 간격 1.5배 | 없음 |
| `V` | 세로줄 삭제 | 팀 (예비) | 일반 블록의 1칸 | Lock | 아이템 칸이 있는 열 전체 삭제 | 지운 칸당 10점 |

`B`·`D`·`S`는 2026-10-09 팀 확정. `V`는 시간이 남으면 4번째로 추가하는 예비 아이템이다. **[확정]**

### 8.1 `L` 줄 삭제 (요구사항 p.8)

- **ITL-1** 일반 블록 7종 중 하나의 값 있는 칸 1개에 붙는다. 위치는 무작위다. 예: I는 `OOOL`, `OOLO`, `OLOO`, `LOOO`가 같은 확률로 나온다. **[확정]**
- **ITL-2** Lock 시 `L` 칸이 놓인 **행**을 그 행이 꽉 차 있지 않아도 지운다(L2에서 R에 추가). 지운 뒤 위 행이 내려온다(CLR-2). **[확정]**
- **ITL-3** 점수는 기존 줄 삭제 방식이다. `L` 행과 같은 Lock에서 완성된 행을 합쳐 `bonus(|R|)`를 한 번 더한다. 같은 행이 완성 행이면서 `L` 행이면 한 번만 센다. **[확정]**
- **ITL-4** `L` 칸이 숨은 줄(row −2, −1)에 놓인 채 Lock되면 그 숨은 줄을 지운다. 점수와 누적 줄에는 포함한다. **[제안]**

| 예시 (Level 무관) | R | 점수 |
|---|---|--:|
| `L` 행만 삭제 | {L행} | +100 |
| `L` 행 + 다른 완성 행 1개 | {L행, 완성행} | +300 |
| `L` 행이 곧 완성 행 | {L행} | +100 |

### 8.2 `W` 무게추 (요구사항 p.9)

- **ITW-1** 형태(너비 4, 높이 2), 회전 불가. 회전 입력은 무시한다. **[확정]**

```text
 WW
WWWW
```

- **ITW-2** Spawn 위치: 너비 4 블록과 같은 규칙(v1.2 SPN-1). 맨 윗줄 `WW`가 보이는 row 0, 앵커 col 3(보드 col 4–5에 `WW`, col 3–6에 `WWWW`). **[제안]**
- **ITW-3** 처음에는 일반 블록처럼 좌우 이동, Soft Drop, 자동 낙하를 한다. **[확정]**
- **ITW-4** **첫 하강 실패**(바닥이나 다른 블록에 닿음, v1.2 LCK-2와 같은 기준) 순간부터 **분쇄 모드**가 된다. **[제안]**
  - 분쇄 모드에서는 좌우 이동이 막힌다(p.9). 입력은 무시한다.
  - 하강 시도(자동 낙하·Soft Drop)마다 한 칸 내려가고, 새 위치에서 무게추와 겹치는 고정 칸을 모두 지운다. 맨 아랫줄이 4칸 폭이라, 지나가는 4개 열의 블록이 모두 지워진다.
  - 첫 하강 실패 순간에도 바로 한 칸 분쇄 하강한다. 무게추가 닿자마자 멈춰 보이는 시간이 없다.
  - 지운 칸 위의 칸은 내려오지 않는다.
- **ITW-5** 무게추의 맨 아랫줄이 보드 바닥(row 19)에 닿은 뒤 다음 하강 시도가 실패하면, 그 자리에 **고정**된다. 셀 값 8(`WEIGHT`)로 기록하고 일반 Lock 파이프라인(§5)을 탄다. 이때 완성된 행이 있으면 평소처럼 지우고 점수를 받는다. **[제안]** **[확인]**
  - 근거: p.9 아래 그림에서 무게추가 바닥에 남아 있다. "바닥에서 사라짐"으로 바꾸려면 ITW-5만 고치면 된다.
- **ITW-6** Hard Drop: 분쇄 모드 여부와 관계없이 바닥까지 한 번에 내려가며 지나는 칸을 모두 지우고 ITW-5대로 고정한다. **[제안]**
- **ITW-7** 무게추로는 점수를 받지 않는다. 하강 점수(v1.2 SCR-1, SCR-2)와 지운 칸 점수 모두 0이다(p.9 "사용이나 지워지는 블럭 등에 대해서는 점수를 부여하지 않습니다"). ITW-5의 줄 삭제 점수는 일반 규칙대로 받는다. **[제안]**
- **ITW-8** 무게추도 Spawn 충돌이면 Game Over다(v1.2 SPN-4). **[확정]**

### 8.3 `B` 폭탄 (팀 아이템)

- **ITB-1** 일반 블록의 값 있는 칸 1개에 무작위로 붙는다. **[확정]**
- **ITB-2** Lock 시 `B` 칸을 중심으로 한 **3×3 칸**(보드 밖은 제외, 숨은 줄 포함)을 지운다. 빈 칸은 그대로 비어 있다. 위 칸은 내려오지 않는다. **[확정]**
- **ITB-3** 3×3 안의 칸이 같은 Lock의 삭제 행(R)에도 속하면 행 삭제로만 처리한다. 칸 점수를 두 번 받지 않는다. **[제안]**
- **ITB-4** 점수: 실제로 지운 **고정 칸(빈 칸 제외) 하나당 10점**. Level과 D 배율의 영향을 받지 않는다. **[확정]**

### 8.4 `D` 점수 2배 (팀 아이템)

- **ITD-1** 일반 블록의 값 있는 칸 1개에 무작위로 붙는다. **[확정]**
- **ITD-2** `D` 블록이 Lock되면 **남은 블록 수 = 10**으로 효과를 시작한다. **`D` 블록 자신의 Lock부터** 줄 삭제 점수(`bonus(|R|)`)가 2배다. **[확정]**
- **ITD-3** 이후 Lock될 때마다 점수를 더한 뒤 남은 블록 수를 1 줄인다(L8). `D` 블록 자신의 Lock은 세지 않는다. 결과적으로 `D` 블록과 다음 블록 10개, 모두 11번의 Lock이 2배다. 0이 되면 효과가 끝난다. **[확정]**
- **ITD-4** 효과 중에 `D`를 또 얻으면 남은 블록 수를 10으로 **다시 채운다**. 배율은 2배로 유지한다(4배로 겹치지 않음). **[확정]**
- **ITD-5** 2배가 되는 것은 **줄 삭제 점수뿐**이다. 하강 점수, `B`·`V`의 칸 점수는 그대로다. **[확정]**
- **ITD-6** 정보 패널에 `x2` 표시와 남은 블록 수를 보여준다. **[확정]**

### 8.5 `S` 슬로우 (팀 아이템)

- **ITS-1** 일반 블록의 값 있는 칸 1개에 무작위로 붙는다. **[확정]**
- **ITS-2** `S` 블록이 Lock되면 남은 블록 수 = 10이 되고, **다음에 Spawn되는 블록 10개**의 낙하 간격이 `interval(Level) × 1.5`가 된다. Spawn할 때 남은 블록 수가 0보다 크면 그 블록을 슬로우 대상으로 정하고 1 줄인다(S3, S4). 0이 되면 끝난다. **[확정]**
- **ITS-3** 효과 중에 `S`를 또 얻으면 남은 블록 수를 10으로 다시 채운다. 배율은 1.5배로 유지한다. **[확정]**
- **ITS-4** Level 계산, 점수, 블록·줄 카운터에는 영향이 없다. 하강 점수는 그대로 `+Level`이다. **[확정]**
- **ITS-5** 정보 패널에 `SLOW` 표시와 남은 블록 수를 보여준다. **[확정]**
- **ITS-6** `D`와 `S`는 동시에 켜질 수 있고 서로 독립적으로 센다. **[확정]**

### 8.6 점수 합산 (v1.2 §6에 더함)

| 항목 | 점수 | Level 영향 | D 배율 |
|---|---|:-:|:-:|
| 하강 1칸 (자동·Soft) | `+Level` (무게추는 0) | O | X |
| Hard Drop | `+d × Level` (무게추는 0) | O | X |
| 줄 삭제 (완성 행 + `L` 행) | `bonus(|R|)` = 100 / 300 / 500 / 800 | X | **O** |
| `B`·`V`가 지운 고정 칸 | 칸당 10 | X | X |
| 무게추가 지운 칸 | 0 | — | — |

**검증 예시**: `D` 효과 중(남은 5) Level 3에서 `B` 블록을 Hard Drop 4칸 → Lock 시 2줄 완성, `B`가 (완성 행 밖의) 고정 칸 5개를 지움 → `4×3 + 300×2 + 5×10 = 662`점, 남은 블록 수 4.

### 8.7 `V` 세로줄 삭제 (예비)

- **ITV-1** 일반 블록의 값 있는 칸 1개에 무작위로 붙는다. Lock 시 `V` 칸이 있는 **열 전체**(숨은 줄 포함)의 고정 칸을 지운다. 위 칸은 내려오지 않는다. 같은 Lock의 R에 속한 칸은 제외한다. 점수는 지운 고정 칸당 10점이다. **[제안]**
- **ITV-2** `V`를 넣으면 ITM-2의 균등 선택 대상에 `V`를 추가한다(각 1/6). 다른 규칙은 바뀌지 않는다. **[제안]**

## 9. 아이템 확장 구조

- **ARC-1** 아이템 하나를 추가할 때 바뀌는 곳은 **`ItemType`에 enum 한 줄 + `ItemEffect` 구현 클래스 하나**뿐이어야 한다. `GameSession`·UI·저장 코드는 고치지 않는다. **[확정]** (p.10 "아이템을 추가하는 것이 어렵지 않도록")
- **ARC-2** 인터페이스 초안 **[제안]**

```java
/** 아이템 종류. 문자는 화면 표시용이며 서로 달라야 한다 (p.7) */
public enum ItemType {
    LINE_CLEAR('L', new LineClearEffect()),
    BOMB('B', new BombEffect()),
    DOUBLE_SCORE('D', new DoubleScoreEffect()),
    SLOW('S', new SlowEffect());
    // WEIGHT('W')는 블록 자체가 아이템이라 별도 블록 종류(WeightBlock)로 둔다 (ARC-3)
}

/** Lock 직후(§5 L2) 한 번 호출된다. 보드를 바꾸지 않고 지울 대상과 지속 효과만 돌려준다 */
public interface ItemEffect {
    ItemResult onLock(BoardView board, int itemRow, int itemCol, GameModifiers modifiers);
}

/** 지울 행·칸. GameSession이 R ∪ C를 모아 CLEARING → 삭제를 수행한다 */
public record ItemResult(Set<Integer> rows, Set<Cell> cells) { }

/** 지속 효과 (점수 배율·낙하 배율과 남은 블록 수). D·S가 여기에 등록한다 */
public final class GameModifiers { /* scoreMultiplier, fallMultiplier, remaining … */ }
```

- **ARC-3** 무게추는 이동 규칙(분쇄 모드)이 달라서 `ItemEffect`가 아니라 블록 종류 `WeightBlock`으로 둔다. `GameSession`의 하강 처리는 `block.isWeight()` 한 곳에서만 분기한다. **[제안]**
- **ARC-4** `BoardView`는 `Board`의 읽기 전용 인터페이스다(`isEmpty(row, col)`, `isRowFull(row)` 등). 아이템 효과가 보드를 직접 바꾸지 못하게 해 삭제 순서(L4)를 `GameSession` 한 곳에서 관리한다. **[제안]**
- **ARC-5** v1.2 §14.2 확장 지점 표에 추가한다. **[제안]**

| 향후 기능 | 교체·추가 지점 |
|---|---|
| 새 아이템 | `ItemType` enum 1줄 + `ItemEffect` 구현 |
| 아이템 등장 확률 조정 | `ItemBlockGenerator`의 `WeightedRandom<ItemType>` 가중치 |
| 난이도 추가 | `Difficulty` enum 1줄 (가중치·step) |
| 다른 블록 분포 | `WeightedBlockGenerator` 가중치 |

### 9.1 파일 구조 추가 (v1.2 §14.3에 더함) **[제안]**


## 12. 렌더링

- **RND-7** (v1.2 RND-4 변경) 기본 블록 칸은 블록 색 배경에 **모두 같은 문자 `O`**를 그린다. 블록 종류는 색으로 구분한다. **[제안]** **[확인]**
  - 이유: p.7은 "아이템은 기본 블럭과 다른 문자를 사용"하라고 하고 p.8은 줄 삭제 아이템을 `L`로 정했다. 기존처럼 블록 칸에 `I/J/L/O/S/T/Z`를 쓰면 L 블록의 `L`과 L 아이템이 같은 문자가 되고, S 블록과 S 아이템도 같은 문자가 된다.
  - 색맹 모드는 v1.2 RND-6의 Okabe–Ito 팔레트로 계속 구분한다. 원 요구사항의 색맹 항목은 "색상·패턴 조정"이므로 문자 없이도 충족한다.
  - 대안: 아이템 모드에서만 `O`로 바꾸기. 모드마다 같은 블록이 다르게 보이므로 권장하지 않는다.
- **RND-8** 아이템 칸은 **흰 배경(`#FFFFFF`) + 검은 굵은 아이템 문자**로 그린다. 기본·색맹 모드 모두 같다. 현재 블록, Next 미리보기 모두 같은 규칙이다. **[제안]**
- **RND-9** 고정된 무게추 칸(셀 값 8)은 연회색(`#BDBDBD`) 배경에 `W`로 그린다. 움직이는 무게추는 흰 배경 + `W`다(RND-8). **[제안]**
- **RND-10** CLEARING 중인 칸은 흰 배경으로만 그리고 문자를 그리지 않는다(ANI-5). 아이템 칸(흰 배경 + 문자)과 구분된다. **[제안]**
- **RND-11** `BlockPalette`에 셀 값 8과 아이템 칸 색을 추가하고, 문자 결정(`O` / 아이템 문자 / `W`)도 한 곳에 모은다. **[제안]**

## 13. 1차 규칙과의 정합 (p.10)

| 1차 기능 | 2차에서의 처리 |
|---|---|
| 색맹 모드 | 블록 색은 색맹 팔레트. 아이템 칸은 흰 배경 + 문자라 색과 무관하게 구분된다 (RND-8) |
| 설정 저장 | 난이도를 `settings.json`에 저장, 재실행 후 유지 (SET-8, PER-7) |
| 화면 크기 3종 | 아이템 문자·CLEARING 표시는 셀 크기에 비례 (v1.2 RND-5와 같은 글꼴 규칙) |
| 조작키 변경 | 무게추 분쇄 모드의 좌우 이동 무시는 키와 무관하게 적용 |
| Pause / Restart / Quit | CLEARING에서도 동작 (ANI-2). Restart는 같은 모드·난이도 (MOD-3) |
| 스코어보드 Top 10 | 분류별 Top 10 (SBD-8) |
| 한글 IME | 변경 없음 (v1.2 KEY-10) |
| 실행 환경 | 변경 없음 (Java 21, Swing, jpackage) |
